# SecureOps E 파트 · 보안 조치 및 재검증

박태준 · 팀 검토용 초안 · Ubuntu 24.04 LTS 기준

공통 기준표와 JSON v1.1을 바탕으로 SSH-01과 FILE-01의 조치 절차 정리. 첫 모의 조치 대상으로 SSH-01 제안. FILE-01은 파일별 소유자·그룹·권한 기준과 예외를 확인한 뒤 적용 범위 결정.

## 1. 보안 조치 정책표

| 점검 항목 | 조치 전 확인 및 백업 | 승인 후 조치 방향 | 재검증 |
| --- | --- | --- | --- |
| SSH-01 · root 원격 로그인 제한 | 일반 관리자 계정으로 SSH 접속과 `sudo` 사용 확인. 기존 관리 세션 유지. SSH 설정과 포함 파일, 복구 경로 확인. 변경 대상 설정 백업. | root에 적용되는 유효 설정을 `PermitRootLogin no`로 변경. 구문 검사 통과 후 설정 반영. | root 접속 조건에서 유효 설정 재확인. 일반 관리자로 새 SSH 접속 및 `sudo` 사용 확인. |
| FILE-01 · 중요 파일 소유자·권한 | 취약으로 판정된 파일과 위반 항목 확인. 파일 유형과 ACL 확인. 기존 소유자·그룹·권한 기록. | 승인된 파일별 기준에 따라 위반 항목만 수정. 기준이나 예외가 불명확하면 조치 보류. | `stat`으로 소유자·그룹·권한 확인. 관련 인증과 서비스 동작 확인. |

공통 조건은 진단 결과가 `vulnerable`이고 대상·항목·변경 범위가 승인된 경우. 실제 조치는 격리된 실습 VM에서 백업과 복구 경로 확인 후 진행하는 안으로 검토.

## 2. 재검증 흐름도

```text
진단 결과 확인 → 조치 대상과 변경 내용 확정 → 관리자 승인 확인
  ├─ 승인·사전 조건 미충족 → 조치 보류 및 사유 기록
  └─ 조건 충족 → 백업 → 조치 → 변경 설정과 정상 동작 확인
       ├─ 조치·설정 검증 실패 → 백업으로 복구 → 복구 결과 기록
       └─ 설정 검증 통과 → 동일 항목 재진단
            ├─ 양호 전환 → 개선 기록
            ├─ 취약 유지 → 미개선 기록
            └─ 재진단 실행 오류 → 오류 별도 기록 → 원인 확인
```

전후 진단 결과는 같은 `target_id`와 `check_id`로 비교하고, 재점검 결과에는 새 `scan_id` 사용. 동일 항목이 `vulnerable`에서 `pass`로 바뀌고 정상 동작까지 확인된 경우 개선으로 기록.

결과에 관리자 승인 내역, 조치 전후 상태, 재진단 판정 또는 실행 오류, 복구 여부와 결과 기록.

## 3. 테스트 계획

자체 샘플 JSON과 가상 SSH 설정값을 사용해 조치 흐름 확인. 아래 항목은 공유용 초안의 검증 계획.

| 확인 항목 | 테스트 방법 | 기대 결과 |
| --- | --- | --- |
| 변경 계획 미리보기 | SSH-01 취약 샘플로 조치 계획 조회 | 대상과 변경 내용 출력, 가상 설정값 유지 |
| 승인 및 상태 확인 | 승인 누락 또는 `needs_review`·`error` 상태 입력 | 조치 보류 및 사유 기록 |
| 조치 후 재검증 | 가상 승인 후 SSH-01 모의 조치, 같은 대상·항목의 양호 결과를 새 `scan_id`로 입력 | 조치 전후 판정과 개선 여부 기록 |
| 잘못된 전후 비교 | 재점검 결과의 대상·항목을 바꾸거나 기존 `scan_id` 재사용 | 비교 거부 |
| 조치·설정 검증 실패 | 가상 설정 변경 도중 오류 또는 변경 설정 검사 실패 발생 | 백업으로 이전 가상 설정 복구 및 결과 기록 |
| 재진단 실행 오류 | 설정 검증 통과 후 모의 재진단에서 실행 오류 발생 | 오류 별도 기록 및 개선 판정 보류 |

검토 요청 사항은 SSH-01 우선 시연 범위와 FILE-01 파일별 적용 기준. 팀원 코드 연동과 실습 VM 조치 일정은 별도 협의.
