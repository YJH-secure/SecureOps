# SecureOps

### Linux 서버 취약점 진단 및 보안 조치 자동화 시스템

**KT 클라우드 사이버보안 부트캠프 | 6인 팀 프로젝트**

개발 기간: 2026.11.04 ~ 2026.12.01  
프로젝트 상태: 설계 및 개발 준비 단계

## 1. 프로젝트 소개

SecureOps는 Linux 서버의 보안 설정을 자동으로 진단하고, 취약점의 위험도를 평가하여 관리자 승인 기반 보안 조치와 재검증을 수행하는 통합 보안 관리 시스템입니다.

단순한 취약점 탐지에 그치지 않고, 진단부터 개선 결과 검증까지 연결하는 것을 목표로 합니다.

## 2. 주요 구현 목표

- Linux 서버 보안 취약점 자동 진단
- 계정·인증 및 시스템·서비스 보안 설정 점검
- 진단 결과 통합 및 위험도 평가
- 관리자 승인 기반 보안 조치
- 조치 전후 비교 및 재검증
- Ubuntu 및 Rocky Linux 환경에서의 호환성 검증

## 3. 팀 구성 및 역할

| 담당자 | 역할 | 주요 업무 |
|---|---|---|
| 양지혁 (팀장) | 보안 아키텍처 및 총괄 | 시나리오·보안 정책·시스템 설계·통합 검증 |
| 김민우 | 서버·네트워크 인프라 | Linux 서버 및 네트워크 환경 구축 |
| 최종욱 | 계정·인증 보안 진단 | SSH·비밀번호·계정 보안 점검 |
| 김서후 | 시스템·서비스 보안 진단 | 파일 권한·서비스·로그 설정 점검 |
| 조효민 | 진단 자동화·위험도 평가 | Python 기반 진단 결과 통합 |
| 박태준 | 보안 조치·재검증 | 승인 기반 조치 및 개선 결과 확인 |

## 4. 개발 환경 (초안)

- 가상화: VMware Workstation
- 중앙 관리 서버: Ubuntu Server 24.04 LTS
- 진단 대상: Ubuntu Server 24.04 LTS / Rocky Linux 9 계열
- 개발 언어: Python 3.12 기준 / Bash
- 개발 도구: VS Code
- 협업: Git / GitHub
- 데이터 형식: JSON

※ 개발 환경은 실제 구축 및 호환성 검증 과정에서 조정될 수 있습니다.

## 5. 시스템 처리 흐름

1. Linux 서버 및 네트워크 환경 준비
2. 계정·인증 및 시스템 보안 취약점 진단
3. 진단 결과 수집과 위험도 평가
4. 관리자 승인 후 보안 조치
5. 재진단을 통한 개선 결과 확인

## 7. GitHub 협업 규칙

- 각 담당자는 본인의 작업 영역을 기준으로 개발합니다.
- 작업은 기능별 브랜치에서 진행합니다.
- 기능 완료 후 Pull Request를 작성하여 검토받습니다.
- 테스트를 통과한 변경 사항만 기본 브랜치에 병합합니다.

- 각 기능의 동작 원리와 테스트 결과를 함께 기록합니다.
