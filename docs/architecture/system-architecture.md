# SecureOps 시스템 아키텍처 설계서

**문서 버전:** v0.1 (초안)  
**작성 담당:** 양지혁  
**관련 Issue:** ARCH-01 (#2)  
**상태:** 설계 검토 중

## 1. 설계 목적

SecureOps는 가상의 중소기업 A사가 운영하는 Linux 서버의 취약점을 중앙에서 자동으로 진단하고, 관리자 승인 기반 보안 조치와 재검증을 수행하기 위한 시스템이다.

본 문서에서는 SecureOps를 구성하는 서버의 역할, 기본 통신 방식, 주요 기능을 정의한다.

## 2. 시스템 구성

| 구분 | 운영체제 | 주요 역할 |
|---|---|---|
| 중앙 관리 서버 | Ubuntu Server 24.04 LTS | 자동 진단 실행, 결과 수집, 위험도 평가, 승인 및 조치 관리 |
| 진단 대상 서버 A | Ubuntu Server 24.04 LTS | Linux 보안 설정 진단 및 조치 기능 검증 |
| 진단 대상 서버 B | Rocky Linux 9 계열 | 다른 Linux 배포판에서의 호환성 검증 |

※ 운영체제 버전과 서버 사양은 구축 과정에서 최종 확정한다.

## 3. 원격 진단 방식

SSH 기반 Agentless 방식을 우선 적용한다.

중앙 관리 서버가 사전에 등록된 진단 대상 서버에 SSH로 접속하여 보안 설정을 점검하고 결과를 수집한다.

대상 서버에는 별도의 SecureOps 전용 에이전트를 설치하지 않는 구조를 기본으로 검토한다.

## 4. 주요 처리 흐름

1. 중앙 관리 서버에서 진단 작업 시작
2. 진단 대상 서버에 SSH 연결
3. 계정·인증 및 시스템 보안 설정 점검
4. 진단 결과를 JSON 형식으로 수집
5. 취약점 위험도 평가 및 결과 보고
6. 관리자 승인 여부 확인
7. 승인된 보안 조치 수행
8. 보안 설정 재검증 및 개선 전후 비교

## 5. 보안 설계 원칙

- 취약점 진단 기능은 기본적으로 읽기 전용으로 구현한다.
- 실제 보안 설정 변경은 관리자 승인 후에만 수행한다.
- 진단 권한과 보안 조치 권한을 분리한다.
- SSH 인증 정보와 민감한 설정값을 GitHub에 업로드하지 않는다.
- 조치 전 백업과 복구 절차를 확보한다.
- 모든 실습은 허가된 가상 서버 환경에서 수행한다.
