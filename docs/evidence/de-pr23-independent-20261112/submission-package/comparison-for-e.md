# 태준님 공유용 — 검증 범위 비교

고정 기준은 D 62d1bf72ef52c7455bc0c2dd624206eb8350f925 / E b0ef73a1613ebc40fdd596edcbaf0413d32309b8입니다.
최신 origin/main도 같은 D SHA로 확인됐습니다.

저희 기존 실제 실행 환경은 Windows 11 / Python 3.14.2 / jsonschema[format] 4.26.0이며,
E 123개 + D CVSS 52개 + C 29개 = 204개가 모두 통과했습니다.
D 독립 8개와 결합 회귀 181개도 실패·오류·Skip 0입니다. 이번 정리 단계에서 이 실행을 다시 했다는 의미는 아닙니다.

실제 ID 비교 결과:

- 공개된 과거 184개 로그의 모든 ID가 저희 204개에 포함됩니다.
- 추가 20개는 execution_history_fields 10개와 execution_history_versions 10개입니다.
- 204와 결합 181은 76개가 겹치고 독립 8개도 결합 181에 포함됩니다.
- 총 393회 실행이지만 고유 ID는 309개입니다. 동일 ID의 소스 파일 내용도 일치했습니다.

태준님이 보고하신 최신 204개 원본 stdout은 공개 저장소에서 확인하지 못했고,
공개 184개 로그를 최신 204개 증거로 대체하지 않았습니다.
최신 204개 원본 결과의 비식별 사본·실제 실행 시각·환경 정보가 있으면 상호 검토를 보강할 수 있습니다.

Python 3.12 실행기는 현재 노트북에서 찾지 못해 독립 재실행은 미실행입니다.
따라서 태준님 3.12.14 결과를 저희가 3.12에서 재현 완료했다고 표시하지 않았습니다.
실행 가능한 3.12 환경이 제공되면 원본 테스트·기대값을 유지하고 별도 결과로 추가할 예정입니다.

D 보고서 16건과 E 이력 9건은 분리 보존하고 새 프로세스로 재조회했습니다.
롤백 후 미재진단은 미확인, 저장 후 조회 실패는 scan ID를 유지하고 성공으로 판정하지 않는 동작을 확인했습니다.
E 이력 1.0과 D 진단 1.1/1.2는 혼용하지 않았습니다.

공통 실행 계층 계약, 명시적 E 이력 저장 호출과 운영 저장 정책은 후속 협의 사항입니다.
실제 SSH/VM·운영 조치/복구는 미검증이며 코드·기존 증거·PR은 변경하지 않았습니다.
