## 2. 당장 이어질 실행 순서와 실패 시 기준

1. **팀장 + A(11/12~13)**: `ssh -G` 별칭·접속 user/port/key 파일명, 대상 `sshd -T -C`의 `addr/host/user` 문맥, 기존 `secureops-scan` sudoers와 별도 SSH01 sudoers 설치 여부 확인. 설정 변경 전 별도 승인.
2. **팀장(11/13~16)**: PR #24 코드·README, #26 실행기(두 파일) 및 main 기반 로컬 180·C163 회귀 증거 보존. 안전한 승인 후 새 VM 한 대 SSH01 수집→B→D 원시 결과/저장·재조회.
3. **D(11/16)**: 실제 JSON의 `target_id/os/scanned_at/scan_id`, 상태/CVSS null, 보고서 재조회 원본 검증. **MOCK 데이터를 실측 데이터로 대체 기록 금지.**
4. **C(11/16 이후)**: 대상 VM에서 C 로컬 CLI를 승인된 읽기 전용 방식으로 실행하고 수집 결과를 중앙에 전달. FILE/LOG 원격 metadata 및 허가된 명령 마이그레이션은 추가 설계.
5. **E(11/17)**: 승인·백업·조치·재진단·롤백의 MOCK 화면과 D/E 이력 연결 증거, 운영 조치와 구분된 발표 자료.
6. **실서버 연동 실패 시:** 실패한 정확한 단계·권한·종료 코드·호스트·시각·원인과 실패 로그를 남기고, MOCK 시연에는 `MOCK` 표시. 근거 없이 완료 체크 금지.
