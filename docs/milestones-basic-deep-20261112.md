## 2. 마일스톤별 '범위 동결'

### M1: 11/18 중간 발표 — 구현 성과가 보이는 최소 흐름
- **필수 시연:** central-mgmt → ubuntu-a 또는 rocky-b 한 대에서 `secureops-scan`의 승인된 읽기 전용 SSH-01 → B 판정 → D JSON v1.2 스키마/CVSS/scan_id → 저장·재조회. 실제 실행 전 sudoers 별도 승인·원격 실행 문맥 검증 필요.
- **필수 설명:** 3대 VMware 토폴로지·SSH 키 분리·기존 sudoers 보존, B/C/D 코드와 E MOCK 상태, `pass/vulnerable/error/needs_review/not_applicable` 및 CVSS pending/null 의미.
- **가능하면:** C FILE/SVC/FW/LOG 중 **일반 권한으로 수집 가능한 모듈 1개** 실제 값 시연. 안 되면 C 오프라인 증거를 별도 표기.
- **시연 범위 제외:** GNS3 전체 망 분리, WAF/IDS 완성, 운영용 자동 조치, 웹 분석 3건 완성, 완제품 대시보드. 발표에서 '후속 단계'로 소개.
- **실환경 실패 대체안:** 네트워크·권한 실패 로그를 보여주고 이미 검증한 MOCK 흐름을 표시하되, 실환경 성공으로 말하지 않는다.

### M2: 12/02 기본 최종 — 4단계 필수 과제와 제출물
- **1단계 인프라:** 중앙 1대 + Ubuntu/Rocky 대상 2대의 실제 SSH, 서버 역할/주소/수집권한/백업·복원 기록. GNS3는 기존 VMware와 실제 연동된 **작은 토폴로지·정책 검증부터** 확장.
- **2단계 자동 진단·조치:** B SSH-01 중심 + 실행 가능한 추가 B 항목, C FILE/SVC/FW/LOG의 승인된 조회·보수적 `needs_review`; E 관리자 승인·백업·재진단·롤백 MOCK, 가능한 경우에만 허가된 VM에서 복구 가능한 **1개 제한된 조치** 실환경 검증.
- **3단계 통합:** D JSON v1.2/CVSS 검증·집계·저장·재조회, 자동 반복 실행과 **최소 대시보드/결과 화면**, 실행 실패 격리·감사 이력. 오프라인 증거와 2개 OS 실제 증거 별도 표기.
- **4단계 웹:** 승인된 격리 웹 실습 대상에 SQLi/XSS/파일 업로드 각 1건의 테스트 조건·관찰·영향·개선안·재검증 보고서 **총 3건** 제출. 실환경 권한이 없는 공격은 수행하지 않는다.
- **산출물:** PPT/발표 대본, PDF 결과보고서, 시연 MP4(5~10분, 100MB 이하), 저장소 README 및 재현 명령. 11/30 내부 동결.
- **우선순위 원칙:** 필수 과제 1~4단계가 IDS/WAF/DNS/FTP의 광범위한 추가 구현보다 먼저. IDS/WAF 등은 기본 단계에서 시연 가능하면 포함하되 미구현을 구현으로 표기하지 않는다.

### M3~M4: 심화 프로젝트 — '관제·방어' 중심 확장 **제안**
- 주제 제안: **SecureOps+ — 다중 구역 Linux/웹 서비스의 진단·위협 탐지·승인형 대응 통합 플랫폼**.
- **M3 12/22:** GNS3 내부/DMZ/외부 네트워크 세그먼트, OPNsense 필터링, Suricata 경보, WAF 정책 전후, DNS/FTP/웹 테스트 서비스의 실제 연결·로그. 보안장비·서비스 도입 순서는 안정성에 맞춰 조정.
- **M4 1/11:** 탐지 이벤트와 CVSS/진단 결과를 `target_id/scan_id` 중심으로 연관, 관리자 승인 E 처리·복구 추적, 서비스/정책별 대시보드 및 재진단 결과 비교. 오탐·권한 실패·타임아웃·복원 실패 대응 근거를 남긴다.
- 클라우드 배포·SIEM 연계 등은 선택적 추가 과제로 두며, 허용된 실습 환경·멘토 승인·시간 확보 후에만 포함.

## 5. 완료 표현 규칙

- `구현 완료`: 추적 가능한 PR/커밋에 코드 존재.
- `오프라인 검증 완료`: 테스트 명령·입력 출처·SHA·로그가 있으며 MOCK·fixture임을 표시.
- `실환경 검증 완료`: 어느 VM·시간·권한·실행명령·원시 JSON·저장·재조회 증거로 재현 가능.
- `승인 대기`: sudoers/정책/실제 조치/PR 병합 등 팀장 승인 전 변경 없음.
- 중간발표/기본 최종/심화는 이 네 가지 상태를 혼합하여 일괄 '완료'라고 표기하지 않는다.
