# FW·LOG 운영 정책 승인 상태

팀장 검토 결과에 따라 방화벽 접근 통제와 로그 운영 기준은 승인 대기다.
배포 정책은 기존 policy_version 및 빈 policies 배열을 유지한다.
정상 조회는 needs_review, 필수 조회 실패와 파싱 오류는 error로 기록한다.

FW는 출발지·목적지·프로토콜·포트·IPv4/IPv6와 존·인터페이스 및 네트워크
환경을 확인한 뒤 운영 정책을 확정한다. 수신 소켓이나 규칙 참조 유무만으로
실제 노출·차단 여부를 판정하지 않는다. GNS3와 VMware 검증 결과는 각각의
환경을 명시한다. 현재 제출된 VM 근거는 VMware 환경에서 수집됐다.

LOG는 OS별 필수 보안 로그, 보관 기간, 순환·압축, 접근권한 및 실제 이벤트
기록 기준이 미정이다. 현재 읽기 전용 관측 결과와 설정 후보를 제공하며
승인된 보관 기준 충족으로 판단하지 않는다.

secureops-scan 계정의 권한 후보는 A 담당자와 실제 실행 파일 경로·인자를
대조한 뒤 승인한다. 현재 코드는 일반 실행으로 명령을 조회하며, 실패는
details.errors에 기록한다. sudoers 수정, Python 전체의 관리자 권한 부여,
포괄적 와일드카드 허용은 이번 구현에 포함되지 않는다.

FILE의 passwd UID 0 및 0644 허용 비트 기준은 기존 승인을 유지한다.
passwd 그룹·확장 ACL·링크, Ubuntu·Rocky shadow 후보, SVC 역할별 허용 정책은
별도 승인 대기다. 이번 PR에는 해당 FILE·SVC 코드와 정책 변경을 넣지 않았다.

코드 병합, 운영 정책 승인, 실제 SSH·D 실서버 통합은 각각의 완료 조건이다.
