## 결과 구분

- 전체 독립 교차 검증: E/C 266 + D callback 38 = 304 PASS, FAIL/ERROR/SKIP 0으로 기록됨.
- D04/D05 선택 재실행: 각 1 PASS. 같은 테스트 ID의 재실행이며 고유 테스트 수에 추가하지 않음.
- 304건과 선택 실행은 과거 실행 증거다. 제출 준비 단계에서 새로 실행한 테스트는 없다.
- `rollback=verified`는 MOCK 백업 복구 확인을 뜻한다. 보안상 PASS 또는 실제 서버 정상 상태를 뜻하지 않는다.

## 예상 질문과 답변

**Q. 실제 서버 설정도 자동으로 바꾸나요?**
A. 아니요. 현재 범위는 MOCK입니다. 실제 SSH 연결, 파일 권한 변경, 원격 조치 및 실제 복구는 구현·검증하지 않았습니다.

**Q. FILE-01이 pass로 바뀌었나요?**
A. 아니요. D04 화면의 `Improved: True`는 `permission_improved`만 뜻합니다. 권한 하위 검사 결과와 종합 상태를 분리하며, 종합 FILE-01은 `needs_review`로 보존됩니다.

**Q. 304 PASS에는 D04/D05가 포함되나요?**
A. 304는 E/C 266과 D callback 38의 고유 ID 합계입니다. D04/D05 후속 선택 실행은 그 안의 기존 ID를 반복 실행한 별도 증거입니다.

**Q. D와 완전히 통합됐나요?**
A. 전달된 D callback을 이용한 격리 MOCK 검증은 있습니다. D Core 기준 commit과 주요 Core/규격 파일 6개는 후속 확인됐지만, 전달 callback이 그 commit tree 또는 최종 통합 tree에 연결되는지는 미확인입니다. 실제 운영 호출부·VM 연동은 완료로 주장하지 않습니다.

**Q. 실패 후 롤백되면 성공인가요?**
A. 아닙니다. 조치 결과와 복구 결과, 복구 뒤 보안 재진단은 별도입니다. 재진단을 하지 않거나 검증이 실패하면 최종 보안 상태는 미확인입니다.
